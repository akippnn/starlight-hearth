## Owner findings that opened this slice

- Desktop input and reconnect began working in the signed HS-002 candidate.
- The resulting UI was still DMS's pointer-oriented shell, not the envisioned
  controller-native system.
- Home and shell surfaces lacked deterministic focus, semantic hints, and
  predictable controller-only navigation.
- Therefore HS-002 is retained only as the **Controller Input Handoff
  Prototype** and is superseded without acceptance.
## Current automated evidence

- `starlight-hearth` repository contracts: **41 passed locally**.
- The v3 Desktop profile contains one D-Bus mapping for every discrete frozen
  control and no controller-to-keyboard target mapping.
- The local cross-repository checker reports that the v3 profile matches the
  current Shell controller destination, object path, interface, and bindings.
- Hearth Shell source contracts: **15 passed locally** after the current
  implementation changes.
- On Fedora 44 x86_64, the locked Rust service compiled and **15 unit tests plus
  3 real D-Bus contract tests passed**. The D-Bus suite exercises the public
  user-bus interface, ObjectManager discovery, input signals, exact mouse-target
  selection, and `SendButton` calls.
- On Fedora 44 x86_64, **8 QML focus/layout tests passed** with
  `QT_QPA_PLATFORM=offscreen`; `HearthFocusGraph.qml` and
  `HearthLayoutPolicy.qml` also pass `qmllint`. The fixtures include 1280x720,
  logical 1920x1080, hidden-node skipping, and semantic focus restoration after
  result reordering.
- The complete frozen upstream Go suite passes with Fedora Go 1.26.6 after
  removing macOS AppleDouble files created only by the SSH transfer. The
  repository and Linux CI checkout do not contain those sidecars.
- `Cargo.lock` is generated and the release workflow now fetches the exact
  locked graph once before running Rust tests and RPM compilation with
  `--frozen --offline`.
- The bounded probe contract keeps the conventional gamepad profile until the
  Shell publishes a versioned probe, permits the semantic profile only for the
  validation window, and restores the gamepad profile on timeout. The router
  counts and drops discrete events until live D-Bus and mouse-button targets
  satisfy the complete readiness contract.
- Rust formatting, JSON parsing, Python syntax, shell syntax, and both
  repositories' whitespace checks pass locally.
- Upstream interface review proved that InputPlumber 0.78 exposes
  `MoveCursor` but no mouse-button method and no composite `SendEvent`. The
  Shell client now requires the versioned ADR-0004 contract and fails closed;
  the corresponding patched RPM remains pending.

A preliminary Fedora 44 x86_64 RPM built successfully and passed checksum,
payload, compatibility-provide, executable, embedded-QML, and layout-validation
checks. Unit verification then exposed a missing `procps-ng` runtime dependency
for `dms.service`; the spec and CI gate are corrected locally. That preliminary
artifact is superseded and is **not** release evidence. The corrected RPM
rebuild, Bazzite RPM validation, InputPlumber schema/extension proof, nested niri
smoke, signed image, hardware measurements, and owner workflow remain pending.
