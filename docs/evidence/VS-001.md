## BlueBuild expansion evidence

to the digest above. Expansion exposed an integration defect: setting
`blue-build-tag` to `v0.9.37-installer` produced the nonexistent
`v0.9.37-installer-installer` image reference. The recipe and regression test
now pin `v0.9.37`; corrected expansion emits exactly
`ghcr.io/blue-build/cli:v0.9.37-installer` and the Containerfile digest above.

evidence. Repeated attempts to refresh every remote module schema were
intermittently interrupted by DNS/timeouts at `schema.blue-build.org`; this did
not change the generated artifact and remains external transport evidence, not
a completed image-build result.

## Upstream contract evidence

- DMS Fedora packaging and niri setup were inspected at the DMS revision above.
- DMS documents `dms.service`, custom theme settings, and IPC actions used by the Hearth bindings.
- Pinned DMS source review showed that bare `dms setup` prompts interactively and may request a privileged input-group change. It was removed from automatic session startup; Hearth supplies the minimal niri integration directly.
- niri remains the Fedora package and starts through `niri-session`; configuration is validated by the candidate gate.
- The target's `steamosctl 26.4.1` exposes every command used for desktop-session selection and Gaming/Desktop transitions. Its live session list format is covered by the adapter parser.
- The target session-manager log identifies `/usr/share/steamos-manager/user.d/config.toml` as its packaged configuration drop-in. An initial `/etc/steamos-manager/config.toml` assumption was rejected, converted into a regression assertion, and replaced before image build.
