## RC.2 signed-image boot and frosted-surface defect — 2026-08-28

The owner rebased and rebooted `aki@hearth` to signed OCI index
`sha256:dea09a20687b3f235b0dd89f817a3a63dcbc24499d1dfa6fa34a813af8f6b191`.
The exact deployment booted successfully, niri started one companion and one
packaged Quickshell UI, and the shell loaded automatically on entering hearthOS
Desktop. This closes the packaged startup gap but does not make RC.2 a passing
candidate.

With the launcher closed and `Launcher1.Visible=false`, a gray frosted
rectangle remained at the drawer location. The authentic layer listing showed
the normal drawer surface still mapped. Product revision `79eae57e…` applied a
niri xray blur rule to that normal namespace, so the compositor blurred the
entire transparent layer even after Quickshell correctly cleared its shaped
background-effect region. Opening the launcher covered the artifact with the
normal panel.

Local shell revision `b17c1bb582090fa2aa294c29a7e97e3b2e5ac3ea` separates
the shaped, xray-fallback, and translucent namespaces. Local product revision
`30fb91dd0ddf1de2ad4afe473663ca789aea5644` scopes niri xray blur to the
explicit fallback namespace. The normal shaped surface stays warm for
immediate opening; only the explicit compositor fallback unmaps after close.
Real-niri staging removed the closed-state artifact across 30 open/close plus
Grid/List cycles. The workload rendered 1,587 frames at p50/p95/p99/max
`0/13/19/19 ms`, kept its `164552704`-byte memory peak unchanged, performed no
measured mesh allocations, and emitted no QML warnings.

The before/after screenshots, layer listings, workload result, and hashes are
under `docs/evidence/artifacts/hsn-001-rc2-frosted-surface/`. Packaged units
were restored afterward. The host therefore remains on the published RC.2,
which still contains this defect; the correction is local evidence only.

The owner has postponed all further public delivery until the HSN-002 stage
and requires an explicit greenlight before any push, tag, RPM publication, OCI
build, or target rebase. This hold does not alter the frozen HSN-001 contract
or convert local proof into release proof.

## Known blockers and limitations

- The owner locally authorized the exact RC.1 rebase and booted the recorded
  signed OCI. This removes the former authorization blocker but does not make
  RC.1 audit-ready.
- RC.1 packaged the QML plugin incompletely, so the installed UI did not start
  reliably during the Gaming Mode to hearthOS Desktop transition. Manual session entry
  could render the launcher, but automatic shell startup failed.
- Controller and keyboard navigation worked and Return to Gaming Mode
  succeeded. Pointer interaction failed. The launcher used oversized spacing,
  poor centering, symbolic placeholders instead of application icons, a heavy
  selected border, and an over-dark scrim that also dimmed the panel.
- In RC.1, Firefox and Dolphin did not remain running. The transient service reported a
  false success while `gtk-launch` descendants escaped the default main-process
  lifecycle, so application survival is not proved.
- RC.1 was visibly laggy and no warmed p95/p99 motion evidence was captured.
  Grid/List persistence, shell-restart survival, receiver reconnect, invalid
  configuration fallback, KDE/TTY recovery, and previous-deployment recovery
  remain untested.
- The gray desktop before manual UI recovery showed that no wallpaper surface
  exists yet. Wallpaper remains outside frozen HSN-001 and is tracked as the
  independent HWP-001 successor work.
- The Fedora workflow RPM and Hearth-local RPM were built from the same clean
  source but are not byte-identical. The sole release identity is the GitHub
  asset SHA-256 below; no bit-for-bit reproducibility claim is made.
- Historical HS-003 tests are salvage inputs only and do not prove this
  contract.
- The owner authorized RC.2 promotion and deployment, but has not recorded an
  HSN-001 acceptance verdict. The signed package and feature image therefore
  exist without implying audit-readiness or acceptance.
- The booted RC.2 image leaves a gray frosted drawer-sized surface visible
  while the launcher is closed. The local two-repository correction passes its
  warm workload, but is intentionally unpublished and uninstalled pending an
  explicit future owner delivery greenlight.
